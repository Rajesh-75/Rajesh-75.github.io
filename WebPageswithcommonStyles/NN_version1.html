Neural Networks

The Architecture of Intelligence

A Neural Network is a powerful Machine Learning model designed to identify complex patterns in data. It is the foundational technology behind modern AI, widely used for Pattern Recognition (such as identifying objects in photos), Image Generation, and Natural Language Processing (like predicting the next word in a sentence).

A Neural Network is one of the few Machine Learning models capable of handling massive amounts of high-dimensional data, such as millions of pixels in an image or billions of tokens in text. Modern Neural Networks are significantly larger than early AI models, both in terms of learnable parameters (the weights) and the depth of internal processing (the number of hidden layers).

Modern Neural Networks require massive computational infrastructure. Training these models on a standard CPU (Central Processing Unit) would take years because CPUs are designed for general-purpose tasks. Instead, modern AI relies on GPUs (Graphics Processing Units) and specialized chips like TPUs (Tensor Processing Units). These processors are built for massive parallelism, allowing them to perform thousands of mathematical calculations simultaneously.

From Linear Regression to Stacks of Logistic Units

Linear and Logistic Regression, as seen in earlier chapters, take inputs, multiply them by weights, and produce an output. A Neural Network is a "multi-layer" stack of linear and logistic regression units. This multi-layer structure allows the model to process data in stages, where each layer leads to the creation of new features and features given to cost function which computes probabilities of the output values.

The Learning Cycle

Training a Neural Network broadly involves four distinct phases. Later in the sections explore the mechanics of each phase in the following sections:

  1. Forward Pass: Data is fed through the network to generate predictions (detailed in Sections 1-4).
  2. Loss Calculation: A function measures how far off the predictions were from the true labels (Section 5).
  3. Backpropagation: The error is propagated backward to compute gradients.
  4. Weight Update: An optimizer (like Adam) uses gradients to update weights.

    By using Activation Functions we allow the network to "bend" the rules, enabling it to learn relationships that aren't just straight lines. These hidden layers automatically combine raw inputs into high-level features.

    Scaling to Deep Neural Networks (DNNs): From Scalars to Tensors

    While shallow networks use individual scalar indices (like $n_1^{(l)}$), a general Deep Neural Network (DNN) scales this architecture across arbitrary depth ($L$ layers) and width ($d_l$ neurons) using full matrix and vector operations.

    For any hidden layer $l$, the entire layer's linear pre-activation vector $\mathbf{z}^{(l)}$ is computed simultaneously via matrix multiplication:

    $$\mathbf{z}^{(l)} = \mathbf{W}^{(l)} \mathbf{a}^{(l-1)} + \mathbf{b}^{(l)}$$

    Where $\mathbf{W}^{(l)} \in \mathbb{R}^{d_l \times d_{l-1}}$ is the weight matrix mapping the previous layer's outputs to the current layer, $\mathbf{b}^{(l)}$ is the bias vector, and $\mathbf{a}^{(l)} = f(\mathbf{z}^{(l)})$ applies the non-linear activation element-wise. This tensor-based formulation allows modern hardware (GPUs/TPUs) to process millions of parameters concurrently.

  • 5. Final Layer (L4) & Loss Evaluation

    Before the final output is emitted, the weighted sums (Logits or $Z$ values) are passed through a non-linear activation function $f(\mathbf{z})$. This function "interprets" the raw scores to match the mathematical requirements of the specific task:

    • Multi-Class Classification (e.g., Softmax): Maps $Z$ values to a categorical probability distribution where $\sum P_i = 1$. This is used when classes are mutually exclusive.
    • Binary Classification (Sigmoid): Squashes a single $Z$ value into a $(0, 1)$ range, representing the probability of the positive class.
    • Regression (Identity/Linear): A pass-through activation used when the goal is to predict a continuous scalar value (e.g., price or coordinate).

    In the architectural flow, L4 outputs values represented as $y_i$ (the Network Prediction). The Loss Function, denoted as $f(y_i, t_i)$, measures the discrepancy between these predictions and the Target Output ($t_i$).

    The Loss Function is parameterized by the weight values $w_i$, often expressed as $L(y_i, t_i; w_i)$. It determines the "cost" or deviation of the network output from the expected target. The mathematical formulation of this error depends strictly on the nature of the problem, as summarized in the table below:

    Loss Function Output Characteristics Primary Use Case
    Mean Squared Error (MSE)
    $$L(w) = \frac{1}{n} \sum_{i=1}^{n} (y_i - t_i)^2$$
    		A positive scalar representing average squared distance. Penalizes large errors heavily. Regression: Predicting house prices or coordinates.
    Mean Absolute Error (MAE)
    $$L(w) = \frac{1}{n} \sum_{i=1}^{n} |y_i - t_i|$$
    		A positive scalar representing average absolute distance. Regression: Use when data contains many outliers.
    Binary Cross-Entropy (BCE)
    $$L(w) = -\frac{1}{n} \sum_{i=1}^{n} [t_i \ln y_i + (1 - t_i) \ln(1 - y_i)]$$
    		Measures the distance between two probability distributions (0 or 1). Binary Classification: Yes/No, Spam detection.
    Categorical Cross-Entropy
    $$L(w) = -\sum_{i=1}^{n} \sum_{j=1}^{C} t_{i,j} \ln y_{i,j}$$
    		Compares predicted class distribution against one-hot encoded targets. Multi-Class: Image recognition (MNIST, CIFAR) or LLMs.

Gradient and Back Propogation

Loss function is a surface with several minimums. Some of these minimums are called global minimums and local minimums. A core of the Neural Network training is finding these points. A minimum corresponds to a point where $$\nabla L(w) = 0 ...(5)$$. where $\nabla L(w)$ is the gradient of the Loss Function.Rather than using a single equation to solve (5) for weights, a repetitive, step-by-step method locates the lowest point of error, much like walking down a hill This gradient is computed by differentiating $L(w)$ with respect to weights ($w$).The most straightforward way to use gradient information is to update weights by taking a small step in the opposite direction of the gradient. This is calculated using the formula:$$w(\tau) = w(\tau-1) - \eta \nabla L(w(\tau-1))....(6)$$.In this equation, the positive value $\eta$ is called the learning rate.The symbol $\tau$ represents a discrete time index, representing the specific iteration count within the sequence of weight updates. After each update, the gradient is calculated again for the new weights, and the process repeats. Because the weights constantly move toward the sharpest possible drop in error, this method is known as gradient descent or steepest descent.

AutoGrad for Back Propogation

While gradient descent is theoretically driven by backpropagation via the chain rule, modern deep learning libraries implement this through Autograd—an automatic differentiation engine that programmatically computes exact analytical derivatives to yield the precise parameter gradients $\mathbf{g}_t = \nabla L(\theta_t)$ required for loss minimization. To accomplish this, the engine dynamically constructs a computation graph during the forward pass—recording every intermediate tensor operation along with its local derivative function—which is then traversed in reverse during the backward pass to evaluate local Jacobians and accumulate gradients. Once these gradients are extracted, they feed directly into AdamW,which is discussed below.

The forward pass (top, solid) computes $a_1, a_2, a_3, L$ left to right, and remembers every operation used. The backward pass (dashed red) walks the same graph right to left exactly once, and at each node multiplies the gradient handed to it from downstream by that node's own local derivative — the chain rule, applied mechanically. This single backward sweep is what fills in every $\partial L/\partial w_i$ used by Eq. (6).

Vanishing and Exploding Gradients: A Consequence of the Chain Rule

The backward sweep above multiplies local derivatives together, layer after layer. For a weight sitting near the input of an $L$-layer network, that gradient is a product of roughly $L$ terms:

$$\frac{\partial L}{\partial w^{(1)}} \;=\; \frac{\partial L}{\partial a^{(L)}} \cdot \prod_{l=2}^{L} \Big( h'\big(z^{(l)}\big)\cdot w^{(l)} \Big)$$

If each of those $L-1$ factors is, on average, smaller than 1 — which is almost guaranteed with Sigmoid (whose derivative $f(z)(1-f(z))$ maxes out at $0.25$) or Tanh — the product shrinks geometrically with depth. A 10-layer Sigmoid network can easily see gradients at layer 1 that are $0.25^{10} \approx 10^{-6}$ times the gradient at the output: the earliest layers effectively stop learning at all, even though nothing in Eq. (6) is technically broken. This is the vanishing gradient problem, and it's precisely what makes the "Vanishing Gradient?" column in the activation-function table below so important. The mirror-image failure, exploding gradients, happens when those factors are consistently greater than 1 (e.g. large weights): the product grows geometrically instead, producing huge, unstable weight updates and — in the worst case — loss values that jump to NaN.

This is not a separate bug to patch — it's a direct, structural consequence of stacking many layers, which is exactly why ReLU's constant derivative of 1 (discussed in the Mathematical Deep Dives section) helps so much, and why the next two sections — principled weight initialization and Batch Normalization — exist: both are specifically designed to keep the magnitude of $h'(z^{(l)})\cdot w^{(l)}$ close to 1 at every layer, so this product neither vanishes nor explodes as depth increases.

All three curves start from the same gradient magnitude at the output layer. Each subsequent step backward multiplies by one more $h'(z^{(l)})\cdot w^{(l)}$ factor — repeatedly below 1 (blue) shrinks it toward zero within a handful of layers, repeatedly above 1 (red) blows it up, and keeping that factor near 1 (green) is the target that initialization and normalization schemes below are built to hit.

Each dashed segment is one optimizer step: the gradient ∇L points toward steepest increase in loss, so the update moves the opposite direction, −∇L, shrinking the loss a little at a time until the parameters settle near the bottom of the bowl — the same θ₁, θ₂ here stand in for any two of the model's billions of weights, with every other weight held fixed for this 2D slice.

Starting from a random $w(0)$ near the rim, each dashed segment is one update from Eq. (6) — a step of size $\eta$ in the direction $-\nabla L(w)$. Repeating this shrinks the loss a little at a time, tracing a path down the bowl wall until the weights settle at the global minimum.

Reality Check: The Loss Surface Is Not a Single Smooth Bowl

The bowl-shaped surfaces above are a useful first picture, but they describe a convex loss — one with exactly one minimum. Real Neural Networks, especially deep ones with millions of parameters, have non-convex loss surfaces: the $(w_1, w_2, \ldots)$ landscape is folded into many separate basins. Each basin bottom satisfies $\nabla L(w) = 0$ just like Eq. (5), but only the single deepest basin is the global minimum; every other basin is a local minimum — a point that is locally "lowest" but not the best solution available anywhere on the surface. Flat, saddle-shaped regions (where the gradient is also near zero but the point is neither a peak nor a true valley) add further difficulty, often slowing training more than local minima do in practice.

Trajectory $w(0)_A$ (red) starts near a shallow basin and gradient descent settles it into a local minimum — the gradient is zero there, so plain gradient descent has no signal telling it to keep moving. Trajectory $w(0)_B$ (blue) starts closer to the deep basin and reaches the global minimum $w^*$, marked with a star. In practice, deep networks have so many parameters that most local minima found in practice turn out to have loss values close to the global minimum, and techniques like momentum, Adam (below), and random-restart initialization all help the optimizer avoid getting permanently stuck in a poor basin or a saddle point.

While standard Gradient Descent uses a fixed learning rate uniformly across all parameters, advanced adaptive variants like Adam (Adaptive Moment Estimation) enhance gradient descent by combining momentum (tracking exponential moving averages of past gradients to smooth trajectories) with adaptive scaling (adjusting step sizes per parameter based on historical variances). The update rule incorporates first ($m_t$) and second ($v_t$) moment estimates:

$$m_t = \beta_1 m_{t-1} + (1 - \beta_1) \nabla L(w), \quad v_t = \beta_2 v_{t-1} + (1 - \beta_2) (\nabla L(w))^2$$
Advanced Gradient Descent: Adam and AdamW Optimization
  • The Role of Adam in Gradient Descent: Adam builds upon standard gradient descent by addressing noisy gradients and varying scales across parameters. By computing biased-corrected moment estimates, it dynamically scales the effective learning rate for each weight, enabling rapid convergence through ravines and plateaus in the loss landscape.
  • The Limitation with Standard Weight Decay in Adam: When trying to apply L2 regularization (weight decay) to prevent overfitting within standard Adam, the penalty term is coupled directly into the gradient calculation. Because Adam divides updates by $\sqrt{v_t}$, parameters with large historical gradients receive disproportionately smaller regularization penalties compared to infrequently updated parameters.
  • AdamW (Decoupled Weight Decay): AdamW fixes this discrepancy by decoupling the weight decay step entirely from the adaptive gradient calculations. It computes the momentum and scaling steps strictly using the loss gradients, and then applies a direct weight decay penalty ($\lambda w$) independently at the final update phase:
    $$w_t = w_{t-1} - \eta \left( \frac{\hat{m}_t}{\sqrt{\hat{v}_t} + \epsilon} + \lambda w_{t-1} \right)$$
    This clean separation ensures consistent regularization across all network parameters, making AdamW the standard optimization engine for training robust deep neural networks and large language models.

Weight Initialization: Picking the Starting Point

  • When we use an algorithm like Gradient Descent to train a model, we have to pick a starting value for all the weights (parameters). Think of this as the "starting position" of your hiker on the 3D loss mountain we discussed.
  • Why it matters: Where you start has a huge impact. It determines how fast the model learns and how accurate it will be on new, unseen data — and, as the previous section showed, a careless choice of initial weight scale is one of the most direct ways to trigger vanishing or exploding gradients before training even gets going.
  • The Problem: There isn't a single mathematical "rulebook" that tells us the globally optimal place to start.

That said, initialization is not pure guesswork either. The guiding principle behind modern schemes is to pick the variance of the initial weights so that the variance of activations (forward pass) and gradients (backward pass) stays roughly constant from layer to layer — i.e. so the factor $h'(z^{(l)})\cdot w^{(l)}$ from the vanishing/exploding discussion above starts out close to 1, rather than leaving it to chance:

$$\text{Xavier / Glorot (for Sigmoid, Tanh):} \quad \text{Var}(w) = \frac{2}{n_{in} + n_{out}} \qquad\qquad \text{He (for ReLU):} \quad \text{Var}(w) = \frac{2}{n_{in}}$$

Here $n_{in}$ and $n_{out}$ are the number of incoming and outgoing connections of a layer (the "fan-in" and "fan-out"). Xavier/Glorot initialization is derived assuming a roughly linear, zero-centered activation like Tanh, and balances variance across both directions. He initialization uses only $n_{in}$ and doubles the variance relative to a naive symmetric choice, specifically to compensate for ReLU zeroing out roughly half of its inputs on every pass — without that correction, activations would silently shrink toward zero as they pass through a deep ReLU network. In both cases, weights are typically drawn from a Normal$(0, \text{Var}(w))$ or a matched Uniform distribution; biases are simply initialized to zero.

The Reality: matching the initialization scheme to the activation function (He with ReLU, Xavier with Sigmoid/Tanh) is now standard practice in every major deep learning library — but it is still a well-reasoned heuristic, not a proof of optimality, so some trial-and-error alongside it remains normal.

Batch Normalization: Stabilizing What Each Layer Sees

Good initialization only controls the starting distribution of activations. As training proceeds and weights in earlier layers update, the distribution of values arriving at every later layer keeps shifting underneath it — each layer is perpetually chasing a moving target, which slows training and compounds the vanishing/exploding problem above. Batch Normalization (BatchNorm) addresses this directly by re-centering and re-scaling the pre-activation values within every mini-batch, at every layer, throughout training.

For a mini-batch $B$, BatchNorm computes the batch mean $\mu_B$ and variance $\sigma_B^2$ of $z_j^{(l)}$ across the examples in that batch, normalizes to zero mean and unit variance, and then applies a learnable scale $\gamma_j$ and shift $\beta_j$:

$$\hat{z}_j^{(l)} = \frac{z_j^{(l)} - \mu_B}{\sqrt{\sigma_B^2 + \epsilon}}, \qquad \text{BN}\big(z_j^{(l)}\big) = \gamma_j \hat{z}_j^{(l)} + \beta_j$$

The learnable $\gamma_j, \beta_j$ matter: they let the network undo the normalization if that turns out to be better for a particular neuron, so BatchNorm never strictly reduces what the network is capable of representing — it only removes the uncontrolled drift in scale that would otherwise happen for free. BatchNorm is applied to the pre-activation $z_j^{(l)}$, before the nonlinearity — the opposite side of the activation from where Dropout was applied earlier in this page. A typical layer therefore runs: Linear ($z$) → BatchNorm → Activation ($h$) → Dropout → next layer.

Like Dropout, BatchNorm behaves differently at test time: instead of using the current mini-batch's $\mu_B, \sigma_B^2$ (a single test example may not even come in a batch), it uses a running average of the mean and variance accumulated during training. Using mini-batch statistics (rather than the true population statistics) also injects a small amount of noise into training, which gives BatchNorm a mild regularizing side-effect — but stabilizing gradient flow through deep networks, not regularization, is its primary purpose.

Regularization: Keeping the Network from Memorizing

A large Neural Network has enough parameters to fit its training data almost perfectly — including the noise. When this happens, training loss keeps falling while performance on new, unseen data gets worse; this gap is overfitting. Regularization is the collective name for techniques that trade a small amount of training accuracy for better generalization, effectively keeping the model on the smoother, simpler side of what it's capable of representing.

To even notice this gap, the available data is normally split into three disjoint sets: a training set (used to compute $L(w)$ and update weights via Eq. (6)), a validation set (never used for weight updates — only to check, after each epoch, whether the model is starting to overfit), and a test set (touched exactly once, at the very end, to report a final, unbiased performance number). Early stopping, mentioned below, is defined entirely in terms of the validation set: it is the rising validation loss — while training loss keeps falling — that signals it's time to stop.

Early on, both curves fall together — the model is still underfitting (too simple relative to the pattern). Past the marked point, training loss keeps improving but validation loss turns back up: the model has started memorizing training-set noise (overfitting) instead of learning the general pattern. Early stopping simply means keeping the weights from the point where validation loss was lowest, rather than the weights from the final epoch. Everything else in this section — L1/L2 penalties, Dropout — is aimed at pushing that upturn later, or removing it, without needing to stop early at all.

The most direct approach adds a penalty term on the weights themselves to the loss function, discouraging any single weight from growing too large:

$$L_{reg}(w) = L(w) + \lambda \sum_i w_i^2 \quad \text{(L2 / "weight decay")}, \qquad L_{reg}(w) = L(w) + \lambda \sum_i |w_i| \quad \text{(L1 / sparsity)}$$

L2 regularization shrinks weights smoothly toward zero (it is exactly the $\lambda w$ term AdamW applies at the update step above); L1 regularization pushes many weights to exactly zero, producing a sparser network. These penalty-based methods are the classical form of regularization, and they are also what a shallow network (a single hidden layer, or even plain Logistic Regression) typically relies on: with far fewer parameters and no depth to exploit, shallow models are less prone to the extreme overfitting deep networks can exhibit, so L1/L2 weight penalties, keeping the hidden layer narrow, and early stopping (halting training once validation loss stops improving) are usually enough on their own.

Dropout: Regularization Built for Depth

Dropout is the regularization technique most associated with deep networks specifically, because it exploits something shallow networks don't have much of: many redundant paths through many hidden units across many layers. On every forward pass during training, each neuron in a layer is independently "dropped" — its output forced to zero — with some fixed probability $p$ (commonly 0.2–0.5):

$$\tilde{a}_j^{(l)} = m_j^{(l)} \cdot a_j^{(l)}, \qquad m_j^{(l)} \sim \text{Bernoulli}(1-p)$$

Because a different random subset of neurons is silenced on every pass, no single neuron can become over-specialized or overly dependent on a handful of specific other neurons always being present — the network is forced to learn redundant, distributed representations of the same feature. This is often described as training a different "thinned" sub-network on every mini-batch and implicitly averaging over an enormous ensemble of them. At test time, dropout is turned off and every neuron is active; to keep the expected output magnitude consistent with training, activations are scaled by $(1-p)$ (or, equivalently, scaled by $1/(1-p)$ during training — "inverted dropout" — so no rescaling is needed at inference).

What $m_j^{(l)}$ Actually Is, and Exactly When Dropout Fires

$m_j^{(l)}$ is simply a coin flip attached to neuron $j$ in layer $l$: it is a random variable that takes the value 1 ("keep") with probability $1-p$ and 0 ("drop") with probability $p$. There is one independent $m_j^{(l)}$ per neuron, and — critically — a brand-new set of these coin flips is drawn every single forward pass, i.e. for every mini-batch of every epoch, starting from the very first batch of the very first epoch. Dropout is not "warmed up" or skipped early in training; it is active on step 1 exactly as it is on step 10,000. The only time it switches off is when the model is put into evaluation/inference mode (e.g. model.eval()), at which point every $m_j^{(l)}=1$ and the $(1-p)$ rescaling (or the inverted-dropout scaling already baked in during training) takes over so the outputs stay consistent.

So the mechanics happen strictly inside the forward pass: for each hidden layer being regularized, (1) compute the pre-activation $z_j^{(l)}$ as usual, (2) apply the activation function to get $a_j^{(l)} = h(z_j^{(l)})$, (3) sample the mask $m_j^{(l)}$ fresh, and (4) multiply it in to get $\tilde{a}_j^{(l)} = m_j^{(l)} \cdot a_j^{(l)}$, which is what actually gets passed forward to layer $l+1$. Backpropagation then simply routes gradients through the same mask: any neuron with $m_j^{(l)}=0$ on that pass also gets zero gradient, since it contributed nothing to the loss on that particular pass.

On the ordering question — dropout is defined on the layer's output $a_j^{(l)} = h(z_j^{(l)})$, so strictly speaking the activation function runs first and dropout is applied to what it produces, not the other way around. There is one special case worth knowing: because $m_j^{(l)}\in\{0,1\}$ and $\text{ReLU}(0)=0$, for ReLU specifically it makes no numerical difference whether you mask before or after the activation — $\text{ReLU}(m \cdot z) = m \cdot \text{ReLU}(z)$ for a 0/1 mask. That equivalence is ReLU-specific: it does not hold for activations like Sigmoid or Tanh, where $h(0) \neq 0$ (e.g. $\sigma(0)=0.5$), so masking before the activation would silently inject a constant $0.5$ instead of a true zero. That's why the general definition — and any framework's actual implementation — always masks the post-activation output.

Dropout is rarely applied to shallow networks for a simple reason: with only one hidden layer and few units, randomly zeroing neurons removes too large a fraction of the model's total capacity on every step, making training unstable or simply throwing away signal the model can't afford to lose. It becomes effective precisely when there is depth and width to spare — which is why, alongside L2 weight decay, Dropout (and its relatives, like DropConnect and Stochastic Depth) is a default ingredient in training modern deep networks, CNNs, and Transformers.

Universal Approximation capabilities of Neural Networks

Before stating the theorem, it's worth being precise about what is being approximated. Recall from the "Scaling to Deep Neural Networks" section that a single layer computes $\mathbf{a}^{(l)} = h\left(\mathbf{W}^{(l)}\mathbf{a}^{(l-1)} + \mathbf{b}^{(l)}\right)$. Write that whole layer as one function, $f^{(l)}(\cdot) = h\left(\mathbf{W}^{(l)}(\cdot) + \mathbf{b}^{(l)}\right)$. An entire $L$-layer Multi-Layer Perceptron is nothing more than these per-layer functions composed end to end, output of one feeding straight into the input of the next:

$$F(x) \;=\; f^{(L)}\Big(f^{(L-1)}\big(\cdots f^{(2)}\left(f^{(1)}(x)\right)\cdots\big)\Big)$$

This single nested expression, $F(x)$, is the neural network — every weight, bias, and activation on this page exists only to shape this one composite function. Training (Sections 1–5 above) is the process of searching over $F$'s parameters so that $F(x)$ matches the unknown true mapping from inputs $x$ to targets $t$ as closely as possible, as measured by $L(w)$. The Universal Approximation Theorem is a formal statement about exactly this $F$:

It has been mathematically proven (most notably by Cybenko and Hornik) that Neural Networks are Universal Approximators. Using a property known as the 'density' of continuous functions, they proved that a single hidden layer can mimic any continuous relationship between inputs and outputs. While we won't go through the formal proof—which involves complex functional analysis—the takeaway is clear: if a logical pattern exists in your data, a Neural Network is theoretically capable of learning it.

One subtlety worth flagging: the theorem guarantees this for a network with just one hidden layer ($L=2$ in the notation above, counting the output layer), given enough width. Depth — stacking many $f^{(l)}$, as the Deep Neural Network section describes — doesn't unlock any function that a wide-enough shallow network couldn't theoretically also represent. What depth buys in practice is efficiency: reaching a comparably good approximation of $F(x)$ with far fewer total parameters than an extremely wide single layer would need, since each additional layer can reuse and recombine the features the previous layers already built.

Mathematical Deep Dives

The Calculus of ReLU: Why the Gradient is 1

For all values where $z > 0$, ReLU acts as the identity function ($f(z) = z$), meaning its derivative is exactly 1. This allows the "error signal" to pass through the neuron unchanged during training, though if $z < 0$, the gradient becomes 0—a state known as the "Dying ReLU" problem.

Architectural Math: Parameter Counting

To calculate the complexity of a Dense Layer, we multiply the input dimension by the output dimension.

Input Size ($L_1$): n

--------------------------

Note: In Large Language Models, $n$ is often 4096 or higher, leading to millions of connections per layer.

Putting It All Together: The Full Training Loop

Every mechanism on this page — initialization, BatchNorm, Dropout, the loss surface, backprop, Adam/AdamW, early stopping — is a piece of one single loop. It's worth seeing them assembled in the order they actually fire. Weight initialization (He/Xavier) happens exactly once, before training begins — it is not repeated per epoch. Everything after that is a nested loop: an outer loop over epochs, and an inner loop over mini-batches within each epoch. Within a single mini-batch's forward pass, BatchNorm and Dropout sit on opposite sides of the activation function at every layer: BatchNorm normalizes the pre-activation $z^{(l)}$, then the activation $h(\cdot)$ runs, then Dropout randomly zeroes out the resulting $a^{(l)}$ before it moves to the next layer.

The outer dashed box is the epoch loop; the inner dashed box is the mini-batch loop nested inside it. Steps 1–4 repeat for every mini-batch, every epoch, until the validation-loss check says to stop — at which point the frozen weights are used for inference, with Dropout switched off and BatchNorm switched to its running statistics.

What's Next: Specialized Network Architectures

Everything on this page — layers, weights, activations, backpropagation, the loss surface, and regularization — applies to the general, fully-connected Neural Network. In practice, most modern architectures are variations of this same core machinery, specialized for a particular kind of data:

  • Convolutional Neural Networks (CNNs): specialized for grid-like data such as images, using shared, spatially-local filters instead of dense connections.
  • Recurrent Neural Networks (RNNs): specialized for sequential data, maintaining a hidden state that carries information forward across time steps.
  • Large Language Models (LLMs) and Transformers: specialized for language and other sequence modeling tasks, built on the self-attention mechanism rather than recurrence or convolution.

Each of these deserves — and gets — a dedicated, in-depth discussion on its own page, covering the architecture-specific mechanics that build on the foundations introduced here.
