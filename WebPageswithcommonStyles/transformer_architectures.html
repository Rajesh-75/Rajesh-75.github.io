Transformer Architectures

A structured walkthrough of the three core Transformer configurations — Encoder-only, Decoder-only, and the general layer stack — explaining what each is, how it differs internally, and which real-world models use it.

0 Why Three Architectures?

The original 2017 Transformer paper introduced a full Encoder–Decoder architecture for machine translation. Since then, researchers discovered that for many tasks you only need one half of that structure. This gave rise to two specialised families:

  • Encoder-only — reads the full input in both directions, produces rich contextual vectors, used for understanding tasks. Example: BERT.
  • Decoder-only — generates output one token at a time, can only attend to past tokens (causal masking), used for text generation. Example: GPT, Claude.
  • Encoder–Decoder — the original full architecture, used when you need to transform one sequence into another. Example: T5, original Transformer.

All three are built from the same Transformer layer block — the difference is in which layers are present and how attention is masked. The layer stack diagram in Section 3 shows this common building block.

Encoder-only Bidirectional No Understanding, classification, search BERT, RoBERTa
Decoder-only Causal (left-to-right only) Yes Text generation, chat, code GPT, Claude, LLaMA
Encoder–Decoder Enc: bidirectional · Dec: causal Yes Translation, summarisation, Seq2Seq T5, BART, original Transformer

1 Encoder-Only Transformer

An Encoder-only Transformer reads the entire input sequence and produces a rich contextual vector for every token. Because there is no generation happening, every token is free to attend to every other token in both directions — past and future — at the same time. This bidirectional view is what makes Encoder-only models excellent at understanding tasks like classification and search.

The key property — bidirectional self-attention
When producing the output vector for "cat" in "The cat sat on the mat", the Encoder can attend to every word simultaneously — including words that come after "cat". This gives it a richer, more complete understanding of each token's meaning in context. No causal mask is applied.

Figure 1: Encoder-only Transformer (BERT-style). The encoder stack reads the full sentence bidirectionally at every layer. No decoder is present — output vectors are fed to a task-specific head for classification.

Inside one Encoder layer

Every layer performs the same two operations in sequence:

  1. Multi-head self-attention — each token attends to all other tokens, producing attention-weighted representations. A residual connection adds back the original input before layer normalisation.
  2. Feed-forward network — a two-layer MLP applied independently to each token position. Another residual connection and layer norm follows.
$$\text{AttentionOutput} = \text{LayerNorm}(x + \text{MultiHeadAttn}(x))$$ $$\text{LayerOutput} = \text{LayerNorm}(\text{AttOut} + \text{FFN}(\text{AttOut}))$$
Why BERT cannot generate text
Because every token attends to every other token — including future tokens — the model has "cheated" during training by seeing the answer. If you asked it to generate "cat ___", it would already have attended to the blank position. Generation requires causal masking — which the Decoder introduces.

2 Decoder-Only Transformer

A Decoder-only Transformer generates text one token at a time. The key architectural difference from the Encoder is causal masking: when processing token at position t, the attention mechanism is mathematically prevented from attending to any token at position t+1 or beyond. This ensures the model cannot "peek" at future tokens during training or generation.

Causal masking — the defining feature
Attention scores for future positions are set to −∞ before the softmax, which zeroes out those weights. Token at position t sees positions 1, 2, …, t only — never t+1, t+2, … This is what makes generation autoregressive: each token can only be predicted from what came before it.

Figure 2: Decoder-only Transformer (GPT / Claude-style). Causal masking ensures each token only attends to past positions. The dashed feedback arrow shows the autoregressive loop — each predicted token becomes the next input.

The generation loop step by step

  1. Input tokens are embedded and positional encodings added.
  2. All tokens pass through all N decoder layers simultaneously.
  3. The output layer applies softmax over the vocabulary — highest probability token is selected.
  4. That token is appended to the input sequence.
  5. Steps 2–4 repeat until </s> is predicted.
Why each generation step runs all N layers
Even though only one new token is added per step, the entire sequence is processed through all N layers again. This is computationally expensive — which is why techniques like KV-caching exist in production systems, storing the key and value vectors from previous steps to avoid recomputing them.

3 The General Layer Stack

Both architectures above are built from the same fundamental unit — a Transformer layer block. Understanding this block and why they are stacked is the key to understanding why bigger models are generally smarter.

Figure 3: General Transformer layer stack. Every layer has the same architecture but learns its own independent weights. Depth accumulates from basic pattern recognition at layer 1 to complex abstract reasoning at layer N.

Why the same block is repeated — not the same weights

A common misconception is that all layers share the same weights. They do not. Each layer has its own independently learned weight matrices for attention and the feed-forward network. The structure is shared; the parameters are not. This means every additional layer adds a full set of new learnable parameters, allowing it to capture increasingly abstract features of the input.

The output of layer N is the input of layer N+1
The same token vectors pass through every layer, but their values are updated at each step. A "cat" vector entering layer 1 with generic word meaning exits layer 96 carrying deep contextual understanding of what that specific "cat" is doing in this specific sentence. The vector size never changes — only its values become richer.

What comes next — the full Encoder–Decoder Transformer:

The architectures above each use only one half of the original 2017 Transformer. The full version — used for translation, summarisation, and other Seq2Seq tasks — combines both: an Encoder stack that reads the source sequence bidirectionally, and a Decoder stack that generates the target sequence autoregressively, connected by a cross-attention layer inside the Decoder that lets the Decoder attend directly to the Encoder's output vectors at every generation step. This is the Transformer upgrade of the RNN Encoder–Decoder you already studied — and the architecture that replaced Bahdanau Attention's sequential bottleneck with fully parallel processing.
