CNN Training Discussion Summary

A comprehensive overview of our technical discussion on training Convolutional Neural Networks (CNNs), tracked from standard operational workflows to custom medical imaging solutions.

1. Standard Training Workflow Sequence

To systematically approach a new project, we mapped out the industry-standard progression:

  • Data Prep: Cleaning, scaling/normalising pixel values, splitting datasets (Train/Val/Test), and applying geometric/color augmentations.
  • Architecture: Choosing between building a custom network from scratch or leveraging transfer learning with pre-trained backbones (e.g., ResNet, MobileNet).
  • Optimization: Selecting appropriate loss functions (e.g., Cross-Entropy) and optimizers (e.g., Adam), alongside learning rate decay policies.
  • Monitoring: Training in small mini-batches while tracking training vs. validation loss curves to catch under- or overfitting.
STUDENT Q&A

What are "geometric/color augmentations"?

They're label-preserving transformations applied to training images to artificially expand the effective size and diversity of the dataset, forcing the network to learn features that are invariant to irrelevant variation.

  • Geometric (change spatial arrangement): rotation, horizontal/vertical flip, random crop, translation, scaling/zoom, shear, elastic deformation (common in medical imaging to simulate tissue warping).
  • Color / photometric (change pixel intensity, not layout): brightness/contrast jitter, hue/saturation shifts, Gaussian noise injection, random erasing/cutout.

Intuition: a cow is still a cow if you flip the image or brighten it. Exposing the network to these variations stops it from latching onto incidental correlations (e.g., "cows are always in bright green fields"). In code this is a stochastic transform applied on-the-fly to each image before it enters a batch (e.g., torchvision.transforms, albumentations) — not a one-time step that permanently multiplies the dataset on disk.

Elastic deformation specifically: it warps the image locally — like the image is on a thin rubber sheet pushed and stretched unevenly — by moving each pixel according to a random displacement field that's been Gaussian-smoothed so nearby pixels shift in similar directions. This mimics how real tissue stretches, compresses, and shears during slide preparation or natural anatomical variation. It's the augmentation credited with letting U-Net train end-to-end from very few annotated images.

FURTHER READING

  • Ronneberger, Fischer & Brox (2015) — U-Net: Convolutional Networks for Biomedical Image Segmentation — the paper that made elastic deformation famous in medical imaging.
  • Simard, Steinkraus & Platt (2003) — Best Practices for Convolutional Neural Networks Applied to Visual Document Analysis — the original paper defining elastic distortion via a Gaussian-smoothed displacement field.
  • Garcea et al. — Augmenting Medical Imaging: A Comprehensive Catalogue of 65 Techniques — survey with a section on elastic deformation and grid distortion, plus practical caveats.

Ready-to-use implementations: torchvision.transforms.ElasticTransform or albumentations.ElasticTransform.

STUDENT Q&A

How is "training in small mini-batches while tracking training vs. validation loss" actually done?

Mini-batch training: instead of computing the gradient over the whole dataset at once (accurate but memory-prohibitive) or one sample at a time (fast but noisy), the training set is split into batches of, say, 32–256 images. For each batch: forward pass → compute loss → backpropagate → update weights. One full pass over all batches is one epoch — a practical compromise driven by GPU memory and a favorable noise-vs-speed tradeoff.

Tracking loss curves: at the end of every epoch, compute the average loss on the training set and on a held-out validation set (never trained on), and plot both against epoch number.

  • Both curves fall together → healthy learning.
  • Training loss falls, validation loss rises or plateaus → overfitting.
  • Both curves stay high and flat → underfitting.

This is just two numbers logged per epoch and plotted — the "monitoring" is the diagnostic signal that tells you when to intervene, not an algorithm in itself.

STUDENT Q&A

What kind of "fine-tuning models" are we talking about?

This refers to transfer learning: taking a network pre-trained on a large generic dataset (typically ImageNet, ~1.2M images, 1000 classes) and adapting it to a specific task instead of training from random weight initialization. Common backbones: ResNet, MobileNet (edge/low-compute), EfficientNet, VGG, and increasingly ViT (Vision Transformer) variants.

  • Feature extraction: freeze all pre-trained convolutional layers [frozen = the layer's weights are fixed at their pretrained values and never updated; feeding the same image through them on training step 1 or step 5000 produces the exact same output feature map every time], only train a new classification head on top. Good when the new dataset is small and similar in domain.
  • Fine-tuning: unfreeze some or all pre-trained layers [unfrozen = those weights receive gradients and update a little each step, so the same image's output feature map slowly drifts as training progresses] and continue training them at a low learning rate along with the new head. Good when the domain (e.g., medical imaging) differs substantially from natural images.

Why it helps with data scarcity: the early/middle layers of an ImageNet-trained CNN already encode generic, reusable features (edges, textures, simple shapes) — you're only adapting the final task-specific decision boundary, not learning those from zero.

Important: the backbone's output is not the raw input pixels. Each convolutional stage produces a stack of feature maps — e.g. a 256×256×64 tensor (256×256 spatial grid, 64 channels) after an early layer, shrinking spatially and growing in channel depth deeper into the network (e.g. 7×7×512 near the end). Only the very first layer ever sees raw pixel values (typically H×W×3 for RGB); everything downstream is passing learned feature maps forward, and it's those feature maps — not pixels — that get frozen, fine-tuned, or fed into the new head.

Fig. 2 — early frozen layers see raw pixels and learn generic edges/corners; later fine-tuned layers pass domain-specific feature maps (not pixels) on to the new head

2. Core CNN Training Challenges & Mitigations

While foundational innovations solved early absolute "showstoppers" like vanishing gradients, training deep networks still presents significant hurdles:

  • Overfitting & Spurious Correlations: CNNs easily memorize training data or exploit "cheats" (e.g., memorising a green grass background instead of learning what a cow looks like). Mitigation: Data augmentation, dropout, and early stopping.
  • Data & Hardware Scale: Modern architectures processing ultra-high-resolution images create massive memory bottlenecks. Furthermore, fine-tuning models for specialized domains constantly suffers from extreme data scarcity and severe class imbalance.
  • Hyperparameter Tuning: Finding the optimal combination of learning rates, batch sizes, and architectures remains a complex, trial-and-error engineering problem.
STUDENT Q&A

How is hyperparameter tuning actually done "by trial and error"?

Not literally random guessing — there are structured search strategies, roughly in order of sophistication:

  • Manual search: adjust one hyperparameter at a time based on observed loss curves.
  • Grid search: define a discrete set of values for each hyperparameter (e.g., LR ∈ {1e-2, 1e-3, 1e-4}, batch size ∈ {32, 64, 128}) and exhaustively train a model for every combination. Expensive — combinations grow fast.
  • Random search: sample combinations randomly from specified ranges instead of exhaustively; often more efficient than grid search for the same compute budget.
  • Bayesian optimization / automated tools (e.g., Optuna, Ray Tune): build a probabilistic model of how hyperparameters map to validation performance and intelligently pick the next combination to try — an informed search rather than blind trial.

Each "trial" = train the model (or a cheap shortened proxy of it) end-to-end and record validation performance. "Error" = the model doesn't converge well, overfits, or underperforms, prompting an adjustment and retry. It's fundamentally trial-and-error because the loss landscape as a function of hyperparameters is non-convex, expensive to evaluate, and has no closed-form gradient to optimize directly.

3. Data Imbalance Issue in Training

In this section we discuss the challenges posed by data imbalance during CNN training. Standard Empirical Risk Minimization quietly fails whenever a class is severely underrepresented, and it fails in two structurally different ways depending on where the rare classes sit relative to the majority. We first work through a fully numeric example of One-Sided Tail Data, where every rare class fans out on a single side of one dominant class, then contrast it with Two-Sided Tail Data, where two structurally different rare tails flank a majority "normal" class from opposite directions and therefore need a different fix.

3.1 One-Sided Tail Data

Let the total dataset consist of $N = 1000$ images distributed across $K = 25$ anomaly classes. The data distribution follows a severe power-law (long-tail) distribution partitioned into three distinct mathematical operational regimes:

  • Head Tier ($K_{\text{head}} = 1$): Class 1 where $n_1 = 300$ images.
  • Mid Tier ($K_{\text{mid}} = 3$): Classes 2, 3, 4 where $n_k = 80$ images each ($\sum n_k = 240$).
  • Long-Tail Tier ($K_{\text{tail}} \approx 21$): Remaining classes sharing $\sum n_k = 460$ images, characterized by single-digit counts ($1 \le n_k \le 10$) up to $n_k = 22$.
Why This Breaks Training, in Plain Terms:

Cross-entropy loss is just an average over all training examples. Since Class 1 alone supplies 300 of the 1000 images, its gradient contribution dominates that average — the optimizer spends most of its effort getting Class 1 right, because that's where most of the loss (and most of the achievable improvement) comes from.

A class with only 2–3 images barely moves the average loss at all, so its gradient signal is too weak to carve out a stable region for it in the classifier's output space. In effect, the network is never given a strong enough reason to "make room" for that class, so it predicts it correctly close to never.

On top of this, you can't even reliably measure the problem: with only 2–3 examples per rare class, there aren't enough samples to hold some out for validation without leaving almost nothing to train on — so stratified train/test splitting itself becomes unreliable at that tier.

Algorithmic Metrics & Evaluation

To avoid deceptive performance evaluation, precision, recall, and $F_1$ must be evaluated per class $k$, then aggregated globally:

$$\text{Precision}_k = \frac{TP_k}{TP_k + FP_k} \qquad \text{Recall}_k = \frac{TP_k}{TP_k + FN_k} \qquad F_{1,k} = \frac{2 \cdot \text{Precision}_k \cdot \text{Recall}_k}{\text{Precision}_k + \text{Recall}_k}$$

Macro-averaging calculates the unweighted mean of $F_{1,k}$ across all $K$ classes, assigning equal weight to every anomaly type regardless of sample size:

$$\text{Macro-F1} = \frac{1}{K}\sum_{k=1}^{K} F_{1,k}$$

Micro-averaging aggregates individual counts globally and is structurally dominated by the head tier, masking total failure on rare anomalies. Global Accuracy is fundamentally untrustworthy; a naive model predicting Class 1 exclusively yields 30% baseline accuracy while achieving 0% recall across the remaining 24 classes.

Metric Condition Mathematical Diagnostic Immediate Engineering Action

3.2 One-Sided Tail: Algorithmic & Hybrid Solutions

To fix this performance bottleneck without collecting more data, we established a multi-pronged strategy. The objective throughout is to prevent the model from ignoring the single rare tail.

Algorithmic Adjustments

  • Cost-Sensitive Loss: Switch to Focal Loss, $$\mathcal{L} = -\alpha (1-p_{\mathrm{t}})^\gamma \log(p_{\mathrm{t}})$$ which down-weights easy background examples ($p_{\mathrm{t}}$ near 1) via the $(1-p_{\mathrm{t}})^\gamma$ term, forcing the remaining gradient budget onto the hard, rare-tail examples. Alternatively, apply Weighted Cross-Entropy with a single positive class scalar weight ($w_{\mathrm{pos}} \gg 1$).
  • Resampling: Use a batch sampler (like PyTorch's WeightedRandomSampler) to force an artificial 50/50 class balance in every GPU training batch, and apply heavy data augmentation exclusively to the minority-class images.
  • Output / Thresholding: With a single output logit $z \in \mathbb{R}$ passed through Sigmoid, adjust the decision threshold down from $0.5$ (e.g., to $0.15$) to maximize recall for the rare tail.
  • Evaluation Metrics: Move away from plain "Accuracy" and judge the model using F1-Score or AUC-ROC instead (see the Precision/Recall/F1 definitions above).

Integrating Hand-Crafted Medical Feature Extraction

Because your project involves medical imaging, we concluded that injecting traditional, deterministic domain knowledge is an excellent way to compensate for data scarcity.

  • The Hybrid Approach: Build a dual-branch network that extracts abstract global features using a CNN, extracts explicit traditional metrics (like GLCM for tissue texture, LBP for micro-patterns, or Active Contours for geometric boundaries) via hand-crafted algorithms, and concatenates them before the final classification layer.
  • Why it helps: It gives the network a mathematical "cheat sheet," reducing the number of images needed to infer basic structural or texture regularities on its own.

3.3 Two-Sided Tail Distributions

The anomaly problem above is a one-sided long tail: one majority class, and every rare class fans out on a single side of it. A genuinely different (and equally common) pattern is a two-sided tail: a majority class sitting in the middle, with two separate rare tails extending in opposite directions — not two variations of the same kind of rarity, but two structurally different failure directions. As with the anomaly example above, this is still a CNN image classification problem: a camera photographs each manufactured part on the line, and the network classifies that image into one of five ordered categories — Severely Undersize / Undersize / In-Spec / Oversize / Severely Oversize — rather than doing anomaly detection on non-visual sensor readings.

Real industry example: machine-vision quality control with a two-sided tolerance. In manufacturing (machined parts, injection-molded components, semiconductor dies, pharmaceutical tablets), an inline camera captures an image of each part, and a measured feature visible in that image — a shaft's diameter, a coating's thickness, a solder joint's size — has a target value with an Upper Specification Limit (USL) and a Lower Specification Limit (LSL). Most part images land safely inside the tolerance band (the majority, "in-spec" class). But defects can occur in two opposite directions: too small/thin/under-filled (one tail) or too large/thick/over-filled (the other tail) — and each direction typically has its own internal severity levels (mildly undersize vs. severely undersize, for example), so each tail is itself a small long tail. This is standard Six Sigma / Statistical Process Control territory, where Cp and Cpk are the process-capability indices used to quantify how well a process stays within both limits simultaneously. Suppose again a training set of $N=1000$ part images, this time labeled by the ground-truth caliper measurement into the five severity classes above:
$$C_p = \frac{USL - LSL}{6\sigma} \qquad C_{pk} = \min\left(\frac{USL-\mu}{3\sigma},\ \frac{\mu-LSL}{3\sigma}\right)$$
$C_p$ measures whether the tolerance band is wide enough for the process's natural spread ($6\sigma$); $C_{pk}$ additionally penalizes the process for being off-center. A value of $C_{pk} < 1.33$ is the usual signal that off-spec parts (your two rare tails) will keep appearing at a non-negligible rate no matter how tightly you control the mean.

Fig. 4 — illustrative shape of a two-sided tail: one majority class in the middle, two independent rare tails extending in opposite directions, each with its own internal severity levels

Worked example, tying the diagram to $C_{pk}$: suppose the target diameter is $10.00\text{mm}$ with $LSL = 9.90\text{mm}$ and $USL = 10.10\text{mm}$, and the process runs at $\mu = 10.01\text{mm}$, $\sigma = 0.03\text{mm}$. Then:

$$C_{pk} = \min\left(\frac{10.10-10.01}{0.09},\ \frac{10.01-9.90}{0.09}\right) = \min(1.00,\ 1.22) = 1.00$$

A $C_{pk}$ of $1.00$ is below the $1.33$ comfort threshold — which is exactly why, out of 1000 parts, roughly 25 of them (the ~15 severely undersize plus ~10 severely oversize in the figure) fall outside spec even though the process mean is close to target. The undersize tail is thinner than the oversize tail here because $\mu$ sits slightly above center, closer to the USL side.

Why this needs a different strategy than the one-sided anomaly problem above: separating "in-spec" from "defective" is usually the easy part here — undersize and oversize parts tend to look clearly different from good ones. The hard part, just like before, is the fine-grained classification within each tail (mild vs. severe undersize, mild vs. severe oversize), where sample counts drop fast the further out you go — so the same two-stage idea applies, just duplicated on both sides: an easier 3-way split (undersize / in-spec / oversize) first, then two separate few-shot/metric-learning models — one for undersize severity levels, one for oversize severity levels — since the two directions represent physically different failure mechanisms and shouldn't share one embedding space.

The same two-sided-tail shape shows up well beyond machine vision — worth knowing, but note these next three are not image-classification tasks the way our CNN example is; they're included only to show how common this statistical pattern is:

  • Semiconductor chip binning: most chips fall in the target performance bin; unusually slow/high-leakage chips and unusually fast/high-power chips are both rare bins on opposite ends of the same performance metric.
  • Vital-sign / patient monitoring: most readings are in the normal range; bradycardia (too low) and tachycardia (too high) are both rare, clinically distinct alert classes on opposite sides of "normal."
  • Credit risk scoring: most borrowers cluster around medium risk; both excellent-credit and severe-default cases are comparatively rare tails in opposite directions.

3.4 Two-Sided Tail: Algorithmic Solutions

The objective here is to maintain feature discriminability at both ends of the spectrum without letting them cancel each other out or get overwhelmed by the center.

  • Loss Function Adjustment:
    • Switch from single binary classification to Ordinal Cross-Entropy or Multi-Class Focal Loss treating $C = \{\text{Left Tail}, \text{Normal}, \text{Right Tail}\}$ — the same Focal Loss weighting introduced in §3.2 applies here per-class, once for each tail independently.
    • If modeled as a regression task (predicting continuous severity), use Asymmetric Huber Loss or Focal L1 Loss to heavily penalize errors occurring at both low ($y < \theta_{\text{low}}$) and high ($y > \theta_{\text{high}}$) target values.
  • Sampling & Batching: Use Stratified Multi-Tail Samplers (e.g., Triplet Batching) to guarantee that every GPU batch contains a fixed balance — for example $33\%$ Left Tail, $34\%$ Normal, and $33\%$ Right Tail — since plain random sampling starves both tails simultaneously rather than just one.
  • Architecture Modification: Single-sided heads easily learn a linear cutoff, but two-sided tails require non-monotonic decision functions. Adding ordinal anchor heads, or two separate classification branches (Branch A for Left Tail vs. Rest; Branch B for Right Tail vs. Rest), prevents optimization gradient interference between the two opposing extremes.

3.5 Summary: One-Sided vs. Two-Sided Comparison

Dimension One-Sided Tail Data Two-Sided Tail Data
Loss Landscape Dominated by a single massive majority class or normal baseline; gradients pushing towards predicting the nominal state. Tug-of-war between two distinct extreme states, separated by a dominant "normal" middle region. Risks class-collapsing to the middle.
Data Imbalance Asymmetric ($1:N$ where $N \gg 1$). One minority positive class vs. majority negative class. Symmetric or Asymmetric Multi-Region ($N_{\text{left}} \ll N_{\text{mid}} \gg N_{\text{right}}$). Two distinct minority tails flanking a majority center.
Batch Composition Standard random sampling leads to GPU batches containing zero tail samples. Standard random sampling starves both tails simultaneously, or severely over-represents the center.
Boundary Mechanics Single decision hyperplane separating normal vs. extreme tail. Two separate decision hyperplanes (or a non-linear closed manifold) separating Left Tail $\leftarrow$ Normal $\rightarrow$ Right Tail.

Mathematical Formulations of CNN Interpretability

To establish attribution mappings within deep networks, we use gradients of the network's output with respect to either the input pixels or intermediate feature maps, to quantify spatial and feature importance relative to a target classification decision.

1. Vanilla Saliency Maps

Vanilla Saliency measures the sensitivity of a specific input pixel configuration toward a targeted output class logit score. It relies on a first-order (local) Taylor-series approximation of the network's highly non-linear decision function.

Let $I \in \mathbb{R}^{H \times W \times C}$ be the input image, and let $S_c(I)$ be the unnormalized output score (logit) for class $c$, prior to the softmax activation. The local linear approximation around a specific image $I_0$ is:

$$S_c(I) \approx w^T I + b$$
STUDENT Q&A

What is $S_c(I)$, the "unnormalized output"?

In a classification network, the final layer produces one raw real-valued number per class — these are called logits. $S_c(I)$ is the logit for class $c$ given input $I$: just one entry of the vector output by the last fully-connected layer, before it passes through softmax.

Why "unnormalized" matters: softmax turns the logit vector into a probability distribution via $p_c = e^{S_c}/\sum_{c'} e^{S_{c'}}$ — but that normalization couples every class's probability to every other class's logit; if one logit rises, another class's probability falls even if its own logit didn't change. For saliency/Grad-CAM, we want "what makes the network's raw evidence for class $c$ go up or down," independent of competition from other classes — so we differentiate the pre-softmax logit $S_c$, not the post-softmax probability $p_c$.

where $w$ is the gradient of the class score with respect to the input, evaluated at $I_0$ — the direction of steepest local change in the score:

$$w = \left. \frac{\partial S_c(I)}{\partial I} \right|_{I = I_0}$$

To collapse the $H \times W \times C$ gradient tensor $w$ into a single 2D spatial heatmap $M_{\text{Saliency}}$, the maximum absolute gradient magnitude across the channel dimension $C$ is taken at each spatial location:

$$M_{\text{Saliency}}(i, j) = \max_{c'} \left| w_{i,j,c'} \right|$$

2. Grad-CAM (Gradient-weighted Class Activation Mapping)

Grad-CAM operates over high-level, coarse feature spaces. Instead of using raw input-pixel gradients, it takes gradients with respect to the feature activation maps of the network's final convolutional layer, which retains more global semantic localization than pixel-space saliency.

Let $A^k \in \mathbb{R}^{U \times V}$ be the $k$-th feature-map channel produced by the final convolutional layer, where $U$ and $V$ are its spatial dimensions. First, the gradient of the class logit with respect to each activation element is computed:

$$\frac{\partial S_c}{\partial A^k_{i,j}}$$

These localized gradients are then collapsed into a single per-channel importance weight $\alpha_k^c$ via Global Average Pooling (GAP) over the $U \times V$ spatial grid:

$$\alpha_k^c = \frac{1}{U \times V} \sum_{i=1}^{U} \sum_{j=1}^{V} \frac{\partial S_c}{\partial A^k_{i,j}}$$

Finally, the $K$ feature maps are combined as a weighted sum using $\alpha_k^c$, and passed through a ReLU to keep only the features that have a positive influence on class $c$:

$$L_{\text{Grad-CAM}}^c = \text{ReLU}\left( \sum_k \alpha_k^c A^k \right)$$
STUDENT Q&A

Does Grad-CAM happen during or after training?

After. Grad-CAM is a post-hoc interpretability technique, not part of the training loop or loss function.

  1. Train the CNN normally to convergence (or to whichever checkpoint you want to inspect) — training uses ordinary backprop of the loss to update weights.
  2. Take a trained, frozen model. Pick a specific input image and a target class $c$ (usually the predicted class, or the true class if diagnosing a misclassification).
  3. Run one forward pass to get the logit $S_c$ and the feature maps $A^k$ at the chosen convolutional layer.
  4. Run one backward pass — but differentiate $S_c$ with respect to the activations $A^k$, not the loss with respect to the weights. No parameter update happens.
  5. Use those gradients to compute $\alpha_k^c$, then the weighted, ReLU'd combination $L^c_{\text{Grad-CAM}}$ — this produces a diagnostic heatmap, not a gradient step.

The superficial similarity to training (both use backprop) is exactly what causes the confusion. The crucial distinction is what is differentiated with respect to what, and that the weights never change — it's the same autograd machinery repurposed for explanation on an already-finished model, not for learning.

Fig. 3 — Grad-CAM runs after training, on a frozen model, differentiating the logit w.r.t. activations instead of the loss w.r.t. weights

STUDENT Q&A

Grad-CAM pseudocode

The backward pass here differentiates the logit $S_c$ with respect to the activations $A^k$, not the loss with respect to the weights — and nothing gets updated. Two hooks are the whole trick: they tap into a chosen convolutional layer's output and its incoming gradient without changing how the model normally runs.

function grad_cam(model, image, target_class, target_layer):
    model.eval()                        # freeze: no dropout, no batchnorm updates
    model.requires_grad_(False)         # no weight gradients needed at all

    activations = None
    gradients = None

    # hook 1: capture the feature maps A^k during the forward pass
    def forward_hook(module, input, output):
        nonlocal activations
        activations = output.detach()

    # hook 2: capture dSc/dA^k during the backward pass
    def backward_hook(module, grad_input, grad_output):
        nonlocal gradients
        gradients = grad_output[0].detach()

    target_layer.register_forward_hook(forward_hook)
    target_layer.register_full_backward_hook(backward_hook)

    # ---- forward pass ----
    logits = model(image)               # S_c(I) for every class c
    score = logits[0, target_class]     # pick S_c for our target class

    # ---- backward pass (NOT a training step) ----
    model.zero_grad()
    score.backward()                    # populates `gradients` via the hook
                                         # no optimizer.step() is ever called

    # ---- global average pool the gradients -> alpha_k^c ----
    weights = gradients.mean(dim=[2, 3])          # average over H, W per channel k

    # ---- weighted combination of feature maps, then ReLU ----
    cam = sum(weights[k] * activations[k] for k in range(len(weights)))
    cam = relu(cam)

    # ---- upsample coarse map to input image size for overlay ----
    cam = resize(cam, size=image.shape[-2:])
    cam = cam / cam.max()               # normalize to [0, 1] for visualization

    return cam

3. Debugging CNNs with Grad-CAM & Saliency Maps

  • Exposes Data Leakage: They reveal if the model is "cheating" by focusing on background artifacts like text watermarks, scanner borders, or timestamps instead of the actual target object.
  • Diagnoses Feature Misattribution: They show if the model is looking at the wrong part of an image (e.g., surrounding healthy tissue instead of a lesion), indicating it has learned incorrect visual rules.
  • Detects Pixel-Level Underfitting: If Vanilla Saliency displays scattered, uniform noise rather than clear object boundaries, it signals that early convolutional layers have failed to learn meaningful spatial shapes.
  • Validates True Positives: They help verify whether correct predictions were driven by genuine feature recognition or by spurious background correlations.
  • Identifies Blind Spots (False Negatives): They map exactly where the network looked when it missed a target completely, pinpointing whether it was distracted by competing visual elements.

Note: Grad-CAM's resolution is limited to the spatial size of the final conv layer ($U \times V$, typically much smaller than the input image), so it's upsampled for display — it localizes coarse regions well but isn't pixel-precise. For finer boundaries, it's often paired with Guided Backpropagation (Guided Grad-CAM).
