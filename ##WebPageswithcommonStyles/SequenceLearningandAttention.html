The core idea: Very often, increasing the size of the training data set, along with a commensurate increase in the number of model parameters, leads to improvements in performance that outpace architectural improvements or other ways to incorporate more domain knowledge.Large language models are trained instead by self-supervised learning on very large data sets of text, along with potentially other token sequences such as computer code. Large language models become smart not because someone taught them grammar rules or facts directly. Instead, they learn everything just by playing one simple game over and over: “guess the next word.”How it works: The training game: Give the model a sentence like “The cat sat on the ___” and make it predict “mat”. Do this billions of times with text from books, websites, Wikipedia, etc.What it picks up: To get good at guessing the next word, the model is forced to learn: Language: Grammar, spelling, sentence structure Context: What words usually go together, how meaning changes based on surrounding words World knowledge: Facts about history, science, people, culture — because those patterns show up in textPretraining = this whole process: Training on huge amounts of text by repeatedly predicting tokens/words. That’s called “pretraining”. The result: A “large language model” — a model that has absorbed tons of knowledge during pretraining. The fundamental concept that underpins a transformer is attention. The fine-tuning can be done by adding extra layers to the outputs of the network or by replacing the last few layers with fresh parameters and then using the labelled data to train these final layers That is, given a context or prefix of words, a language model assigns a probability distribution over the possible next words.The fundamental intuition of language models is that a model that can predict text (assigning a distribution over following words) can also be used to generate text by sampling from the distribution. In video/image compression: Encoder: Takes a big input like raw video and compresses it into a smaller, dense representation. Throw away redundancy, keep the essence. Decoder: Takes that compressed representation and reconstructs the original output, like pixels on your screen.In Transformers: Encoder: Takes input text and “compresses” it into a dense representation — a set of vectors that capture the meaning and context of every token. It’s not fewer bytes, but it’s a richer, abstracted form. The input “The cat sat” becomes vectors that know “cat” is the subject, “sat” is past tense, etc. Decoder: Takes a representation and “decompresses” it into output text. In seq2seq, it uses the encoder’s representation. In decoder-only like GPT, it uses its own past context to generate the next token.Why the same words? Both are about converting between forms: Generation of next word (Token) Taking the logit vector of u and using softmax generate the probability The simplest way to generate tokens is to always generate the most likely token given the context, which is called greedy decoding Let's break down exactly what the Transformer is doing to your data matrix $X$ (of dimension $N \times D$) during these two stages.Stage 1: The "Attention" Stage (Columns / Cross-Token Mixing)In this stage, the Transformer manages all tokens simultaneously, but it allows them to talk to each other.Mathematically, it looks at the vertical column axis of your matrix. It compares the features of Row 1 (Token 1) with Row 2 (Token 2), Row 3 (Token 3), and so on, all at once.What is happening: The model is asking, "How does the word 'bank' in Row 4 relate to the word 'river' in Row 1?" * The Result: It mixes context across rows. Information flows between different time steps simultaneously through a massive parallel matrix multiplication ($Q K^\top$).Stage 2: The "Feed-Forward" Stage (Rows / Independent Transformation)Once the tokens have shared context with one another, the architecture switches directions completely. It now looks at each horizontal row independently.The network passes each row vector through a mini multi-layer perceptron (a standard feed-forward neural network).What is happening: The exact same mathematical function (weights) is applied to Row 1, Row 2, Row 3... completely in isolation. Row 1's features are transformed using only Row 1's data. Row 2's features are transformed using only Row 2's data.Why this is purely parallel: Because there is no communication between the rows in this stage, a modern GPU chip can calculate the updates for all $N$ rows at the exact same millisecond. It doesn't matter if you have 3 words or 3,000 words; they are all transformed at the same time. ach Row represents: A Specific Token (Time Step)Every single row in the matrix corresponds to one individual token in the sequence, arranged in chronological order from top to bottom.If you are processing text, Row 1 is the 1st word, Row 2 is the 2nd word, and Row $N$ is the last word.If you are processing sensor signals, Row 1 is the sensor snapshot at Time Step $t=1$, Row 2 is the snapshot at Time Step $t=2$, and Row $N$ is the snapshot at the final Time Step.2. Each Column represents: A Specific Feature (Dimension)Every column in the matrix corresponds to a specific feature dimension that describes that token.If you are processing text, these columns are the dense numbers making up the word's embedding vector (e.g., Column 1 might track abstract semantic traits like "royalty", Column 2 tracks "tense", up to Column $D$).If you are processing sensor signals, each column is a different data channel measured at that exact moment (e.g., Column 1 is Voltage, Column 2 is Temperature, Column 3 is Vibration frequency).
