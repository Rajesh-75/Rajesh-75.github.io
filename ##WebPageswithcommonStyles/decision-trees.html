Decision Trees: Entropy and Information Gain

🧠 Introduction to Decision Trees

A Decision Tree is a non-parametric supervised learning algorithm used for both classification and regression. It models decisions by creating a tree structure, where internal nodes represent tests on features, branches represent the outcome of the test, and leaf nodes represent the final class label or value. The goal is to create a model that predicts the value of a target variable by learning simple decision rules inferred from the data features.

Key Algorithms

Several well-known algorithms guide the construction of Decision Trees by determining the optimal way to perform splits:

  • ID3 (Iterative Dichotomiser 3) / C4.5: These algorithms primarily use Information Gain based on Entropy as the splitting criterion. They are designed to find the feature that maximizes the reduction in impurity at each step.
  • CART (Classification and Regression Trees): This algorithm uses the Gini Impurity measure for classification and the Mean Squared Error (MSE) for regression. CART is the most commonly used framework today.
The splitting criterion (Entropy/Information Gain or Gini Impurity) is the core mechanism that drives the tree's construction and performance.

🌳 Core Concepts: Entropy and Information Gain

Entropy Gain is the criterion used to select the best feature split at a node. The split is chosen to achieve the maximum reduction in impurity.

1. Entropy (Impurity Measure)

Measures the disorder or randomness in a set of data. Value ranges from 0 (pure) to $\log_2(C)$ (maximum disorder). A value of zero means no further split is required, and high disorder requires us to split based on the variation in the dataset.

Maximum Disorder (Entropy = 1.0) 🎲

A 50/50 split for a binary classification problem results in an Entropy of $\mathbf{1.0}$. This is the highest possible impurity for two classes.

Concept: This node is maximally uncertain. If you picked a ball at random, your chances of being right (Red or Green) are only $50\%$. The algorithm gains the maximum potential information by splitting this node.

The Math:

$$\text{Entropy}(S) = - \sum_{c=1}^{C} P_c \log_2(P_c)$$ $$\text{Entropy} = - \left[ \left(\frac{5}{10} \log_2\left(\frac{5}{10}\right)\right) + \left(\frac{5}{10} \log_2\left(\frac{5}{10}\right)\right) \right]$$ $$\text{Entropy} = - \left[ (0.5 \times -1) + (0.5 \times -1) \right] = \mathbf{1.0}$$

Perfect Purity (Entropy = 0) ✅

A node containing only one type of item (e.g., 5 Red balls) has an Entropy of $\mathbf{0}$.

Concept: This node is pure (or homogeneous). There is no uncertainty about the class, so no further split is required. This node becomes a leaf node in the Decision Tree.

The Math:

$$\text{Entropy} = - \left[ \left(\frac{5}{5} \log_2\left(\frac{5}{5}\right)\right) + \left(\frac{0}{5} \log_2\left(\frac{0}{5}\right)\right) \right]$$ $$\text{Entropy} = - \left[ (1.0 \times \log_2(1)) + 0 \right] = \mathbf{0}$$

*(Note: In information theory, the term $0 \log_2(0)$ is conventionally treated as $0$).*

This confirms the core rule: The goal of the Decision Tree is to choose splits that drive the Entropy value from a high number (like 1.0) down toward 0.0.

$$\text{Entropy}(S) = - \sum_{c=1}^{C} P_c \log_2(P_c)$$

Example: A node with 5 Red and 5 Green balls has $\text{Entropy} = 1.0$ (maximum impurity for two classes).

2. Information Gain (IG)

The gain is the difference between the parent's entropy and the weighted average of the children's entropies. The feature that yields the highest Information Gain is chosen for the split.

$$\text{Information Gain}(S, A) = \text{Entropy}(S) - \sum_{v \in \text{Values}(A)} \frac{|S_v|}{|S|} \text{Entropy}(S_v)$$

ID3 in Action: Building the Real-World Tree by Entropy

Applying this to the 14-day tennis dataset: the parent set has 9 "Yes" and 5 "No", so $\text{Entropy}(S) = -\frac{9}{14}\log_2\frac{9}{14} - \frac{5}{14}\log_2\frac{5}{14} = 0.940$. Computing the Information Gain for every candidate attribute at the root gives:

AttributeWeighted Entropy After SplitInformation Gain
Outlook0.6940.246 (highest)
Humidity0.7890.151

ID3 always chooses the attribute with the highest gain, so Outlook becomes the root, and — because ID3 handles categorical features natively — all three of its values (Sunny, Overcast, Rain) branch out from the root in a single step. The Overcast branch is already pure (Gain isn't even needed there: 4/4 are "Yes"), so it becomes a leaf immediately. Recursing on the Sunny subset (5 days) finds Humidity gives a perfectly pure split (High → all No, Normal → all Yes); recursing on the Rain subset (5 days) finds Wind gives a perfectly pure split (Weak → all Yes, Strong → all No). ⚖️ Alternative Impurity Measure: Gini Impurity

While Entropy and Information Gain are used by algorithms like ID3/C4.5, an equally popular measure of impurity is Gini Impurity — the criterion used by CART, and the default in most modern libraries (e.g. scikit-learn), because it avoids computing logarithms and is therefore cheaper to evaluate at every candidate split. Like Entropy, Gini Impurity is 0 for a pure node and increases with disorder, with the best split being the one that minimizes the weighted Gini Impurity of the child nodes (equivalently, maximizes the Gini Gain — the reduction in Gini Impurity from parent to children, exactly analogous to Information Gain).

3. Gini Impurity

Gini Impurity measures the probability that a randomly chosen item from the set would be incorrectly classified if it were randomly labeled according to the class distribution of the set. Value ranges from 0 (pure) to a maximum of $1 - \frac{1}{C}$ for $C$ classes (maximum disorder).

$$\text{Gini}(S) = 1 - \sum_{c=1}^{C} P_c^2$$

Maximum Disorder (Gini = 0.5) 🎲

A 50/50 split for a binary classification problem results in a Gini Impurity of $\mathbf{0.5}$ — the highest possible impurity for two classes.

Concept: Just as with Entropy, this node is maximally uncertain: guessing the majority class at random is right only half the time. Note that Gini's maximum (0.5) is numerically different from Entropy's maximum (1.0) for two classes — the two measures use different scales, but they agree on where the impurity is highest and lowest, which is why either can drive tree construction to essentially the same splits in practice.

The Math:

$$\text{Gini}(S) = 1 - \left[ \left(\frac{5}{10}\right)^2 + \left(\frac{5}{10}\right)^2 \right]$$ $$\text{Gini}(S) = 1 - \left[ 0.25 + 0.25 \right] = \mathbf{0.5}$$

Perfect Purity (Gini = 0) ✅

A node containing only one type of item (e.g., 5 Red balls) has a Gini Impurity of $\mathbf{0}$.

Concept: With probability 1 of drawing a Red ball, the chance of a random guess being wrong is zero. This node is pure and becomes a leaf, exactly as with Entropy.

The Math:

$$\text{Gini}(S) = 1 - \left[ \left(\frac{5}{5}\right)^2 + \left(\frac{0}{5}\right)^2 \right]$$ $$\text{Gini}(S) = 1 - \left[ 1.0 + 0 \right] = \mathbf{0}$$

Same rule as Entropy: the goal is to choose splits that drive the Gini value from its maximum down toward 0.0.

Entropy vs. Gini, side by side

For a binary node, both measures are functions of a single probability $p$ (the fraction of the node belonging to one class), and both peak at $p = 0.5$ and vanish at $p = 0$ or $p = 1$. The curves differ only in shape and scale — Entropy rises and falls slightly more sharply near the extremes, which is why it is occasionally more sensitive to small, near-pure splits than Gini.

CART in Action: Building the Real-World Tree by Gini — Binary Only

CART is not allowed to fan a categorical attribute out into all of its values at once — every split must be binary. For a $k$-valued categorical attribute this means searching over all ways to partition its values into two groups. For Outlook ($k=3$: Sunny, Overcast, Rain), that means testing all three possible binary groupings:

Comparing that best Outlook split against the other (already-binary) attributes — Humidity (Gain 0.092), Wind (Gain 0.031), and the best binary grouping of Temperature (Gain 0.016) — {Overcast} vs. {Sunny, Rain} still wins at the root, using the parent Gini of $1 - (\frac{9}{14})^2 - (\frac{5}{14})^2 = 0.459$. So CART agrees with ID3 that Outlook is the most informative attribute — but it can only peel off one value at a time. The 10 non-Overcast days (5 Yes, 5 No) then recurse: the best split there is Humidity (High vs. Normal, Gain 0.18), and each resulting branch still isn't pure, so Outlook and Wind each get reused a second time, deeper in the tree, to finish separating the remaining cases:

Both algorithms agree on the same two most informative attributes (Outlook, then Humidity/Wind) and both reach 100% pure leaves — but CART needs 4 levels of binary splits (and reuses Outlook twice) to express what ID3 captured in 2 levels using multi-way splits. This is the direct, concrete trade-off of "binary-only" splitting: simpler, more uniform split logic (every node asks exactly one yes/no question, which is also what makes cost-complexity pruning and CART's regression-tree extension straightforward) at the cost of deeper trees and repeated use of the same feature.

Multi-Feature Split Scenario (Detailed)

To classify balls by a combination of Circumference ($>$ Val, $\le$ Val) and Color (Red, Green, etc.), it is tempting to combine the features into compound target classes (e.g. "Red Large", "Green Small"). This is not what a decision tree does — the target classes stay exactly as originally labeled (Red, Green, etc.), and the tree evaluates one feature at a time against that unchanged target. The actual split-search procedure, at every node, is:

  1. Keep the target classes fixed as given in the dataset (e.g., Red, Green) — the split search never redefines or combines them.
  2. For each feature independently (Circumference, Color, ...): for a numerical feature, test every candidate threshold Val present in the data (splitting into $\le$ Val and $>$ Val); for a categorical feature, test each candidate grouping of its categories.
  3. For every (feature, threshold) candidate, compute the resulting Information Gain (or Gini Gain) of that single-feature split relative to the parent node's impurity.
  4. Across all features and all thresholds considered together, choose the single (feature, Val) pair that produces the maximum gain — this one winning split is applied at the node, producing exactly two children (for CART) or one branch per value (for ID3-style categorical splits).
  5. Recurse independently on each child node, repeating steps 1–4, until a stopping condition is met (node is pure, or a depth/sample-count limit is reached).

In other words, Circumference and Color are never merged into a single combined variable during the search — they are two separate candidate features, each scored on its own, and only the best-scoring one is used at that node. A later node further down the tree may then split on the other feature.

🔒 Regularization: Preventing Overfitting

Left unconstrained, both ID3 and CART will keep splitting until every leaf is perfectly pure — even our tiny 14-row tennis example, if it had one more mildly noisy row, could grow an extra branch just to isolate that single outlier. A tree that memorizes every training example this way generalizes poorly to new data: it has effectively learned the noise, not the underlying pattern. Regularization is what keeps a tree from growing to that extreme.

1. Pre-Pruning (Early Stopping)

These are the stopping conditions already visible in the recursive-build flowchart at the top of this page — they halt growth during construction, before a branch is ever added:

HyperparameterEffect
max_depthCaps how many levels of splits the tree may have, regardless of purity.
min_samples_splitA node with fewer than this many samples is not split further — it becomes a leaf even if impure.
min_samples_leafRejects any candidate split that would leave a child with too few samples (guards against splits that isolate a single noisy point).
min_impurity_decreaseRejects a split unless it reduces impurity (Gini/Entropy Gain) by at least this amount — directly analogous to the flowchart's "Best Gain < 0?" check, generalized to "Gain too small to be worth it".
max_leaf_nodesCaps the total number of leaves the finished tree may have.

2. Post-Pruning: Cost-Complexity Pruning (CCP)

CART's standard approach instead grows the full, unpruned tree first, then prunes it back afterward. It does this by minimizing a cost function that explicitly trades off fit against tree size — a direct structural parallel to L1/L2 weight-penalty regularization in neural networks:

$$R_\alpha(T) = R(T) + \alpha \, |T|$$

Here $R(T)$ is the tree's total misclassification cost (or weighted impurity) over all its leaves, $|T|$ is the number of leaves (the tree's "complexity"), and $\alpha \ge 0$ is a tunable penalty — exactly playing the role that $\lambda$ plays in $L(\theta) + \lambda\lVert\theta\rVert^2$ for a neural network. Increasing $\alpha$ makes each additional leaf more "expensive," so the algorithm prunes back branches whose contribution to reducing $R(T)$ doesn't justify their complexity cost. In practice, $\alpha$ is chosen the same way any regularization strength is chosen: via cross-validation, picking the value that minimizes error on held-out data.

3. Ensembling as Implicit Regularization

A single deep tree is a high-variance model — a small change in the training data can produce a very different tree. Random Forests reduce this variance by training many trees on bootstrapped samples with random feature subsets at each split, then averaging their predictions; Gradient Boosted Trees instead build shallow, heavily-regularized trees sequentially, each correcting the previous ensemble's residual error. Both are beyond the scope of this page but are the practical reason production systems rarely deploy a single, unpruned tree.

🔗 Mapping Decision Trees to the Model → Cost Function → Optimization Framework

Every supervised learning algorithm can be described as three pieces: a Model that produces a prediction, a Cost Function that scores how wrong that prediction is, and an Optimization procedure that adjusts the model to reduce that cost. For a neural network these map to Forward Pass (FP), Cross-Entropy Loss, and Backpropagation (BP) + gradient descent. Here is how a Decision Tree maps onto the same three pieces:

StageNeural NetworkDecision Tree
Model Forward Pass: $\hat{y} = f(x; \theta)$, a fixed composition of linear and nonlinear layers with continuous parameters $\theta$. The tree itself: a nested sequence of if/then feature tests that partitions the input space into axis-aligned regions, each leaf outputting a constant (majority class or class distribution).
Cost Function Cross-Entropy Loss: one global, differentiable scalar computed over the whole dataset (or batch), $L(\hat y, y)$. Entropy/Gini Impurity: a local scalar recomputed at each candidate split, quantifying disorder in that node only — not one global loss over the whole tree.
Optimization Backpropagation computes exact gradients $\partial L/\partial\theta$ via the chain rule; an optimizer (SGD/Adam) iteratively descends the loss surface over many epochs, refining the same parameters each time. Greedy recursive splitting: at each node, exhaustively score every (feature, threshold) candidate and pick the single best local impurity reduction, then recurse. Each decision is made once and never revisited.

Where the Mapping Breaks Down

The high-level three-stage shape holds, but the mechanics underneath are genuinely different in ways worth naming explicitly rather than glossing over:

  1. No global objective. A neural network minimizes one loss function jointly over every parameter. A tree's split search is myopic: it optimizes each node's impurity in isolation, with no lookahead into how that choice constrains splits further down. Two different attributes with near-identical root Information Gain can lead to very differently shaped downstream trees, and the greedy search has no mechanism to notice or correct for this — it can only make the locally best choice at each step.
  2. No gradients — the parameters are discrete. A network's weights are continuous and differentiable, which is precisely what makes backpropagation possible. A tree's "parameters" (which feature, which threshold, at which node) are discrete, combinatorial choices with no defined gradient. This is not an implementation detail: finding the globally optimal decision tree is known to be NP-hard (Hyafil & Rivest, 1976), which is exactly why every practical algorithm (ID3, C4.5, CART) falls back on a greedy heuristic instead of a global optimizer.
  3. No backward pass. Backpropagation explicitly propagates an error signal backward through the composition of layers, updating every earlier parameter based on how it contributed to the final loss. A tree has no analogous step: once a split is chosen, nothing about the leaves' eventual accuracy ever flows back up to revise it. Cost-complexity pruning is the closest thing to a correction, but it happens as a separate, one-time post-processing pass over the finished tree — not as a continuous feedback loop.
  4. No iterative refinement. Network training repeats forward/backward passes over many epochs, gradually improving the same set of parameters. A single tree makes each split decision exactly once, in one pass, top-down. There is no equivalent of "training longer" to improve the same tree structure.
  5. Where it genuinely does match: impurity truly plays the same conceptual role a loss function does — a scalar quantifying "how bad is this arrangement," which the algorithm actively works to reduce. It is simply applied locally and greedily rather than globally and via gradients.

Interestingly, this exact gap is what motivates Gradient Boosted Trees (XGBoost, LightGBM): they reintroduce a single global, differentiable loss and perform gradient descent in function space, fitting each new shallow tree to the negative gradient (residual) of that global loss — explicitly correcting the greedy shortsightedness of a single CART tree. That connection is a good next topic once the LLM Engine work settles.

📜 Pseudocode: ID3 vs. CART

Both algorithms share the same recursive skeleton — score every candidate split, take the best one, recurse on the children — but differ in exactly what gets scored and how a node is allowed to branch.

ID3

function ID3(S, Attributes, Target):
    if every example in S has the same Target value v:
        return Leaf(v)                              # pure node
    if Attributes is empty:
        return Leaf(MajorityValue(S, Target))        # ran out of features

    A ← argmax over a in Attributes of InformationGain(S, a)
    root ← DecisionNode(A)                       # one branch per value of A

    for each value v of A:
        S_v ← { examples in S where A = v }
        if S_v is empty:
            root.addChild(v, Leaf(MajorityValue(S, Target)))
        else:
            root.addChild(v, ID3(S_v, Attributes - {A}, Target))

    return root

CART

function CART(S, depth):
    if StoppingConditionMet(S, depth):     # pure, max_depth, min_samples_split, ...
        return Leaf(MajorityClass(S))

    bestGain ← -∞
    for each feature F:
        for each candidate split v of F:    # threshold (numeric) or category subset
            (S_left, S_right) ← partition(S, F, v)
            gain ← Gini(S) - ( |S_left|/|S| * Gini(S_left)
                                + |S_right|/|S| * Gini(S_right) )
            if gain > bestGain:
                bestGain, bestFeature, bestSplit ← gain, F, v

    if bestGain ≤ 0:
        return Leaf(MajorityClass(S))        # no useful split found

    (S_left, S_right) ← partition(S, bestFeature, bestSplit)
    node ← DecisionNode(bestFeature, bestSplit)   # exactly 2 children, always
    node.left  ← CART(S_left,  depth + 1)
    node.right ← CART(S_right, depth + 1)
    return node

This is the same recursion drawn in the fit / _build_tree flowchart at the top of this page — StoppingConditionMet is the "Stopping Conditions Met?" diamond, and the bestGain ≤ 0 check is the "Best Gain < 0?" diamond.

🏭 Industry Example: Predictive Maintenance in Manufacturing

The tennis dataset is useful for learning the mechanics, but the reason Decision Trees are genuinely popular in industry is different: they're interpretable (a maintenance engineer can read the tree as a checklist, not a black box), they need no feature scaling, they handle mixed numeric/categorical sensor data natively, and once trained, inference is just a handful of comparisons — cheap enough to run directly on an edge device sitting next to the machine, unlike a large neural network. This is exactly why Decision Trees (and their ensemble descendants, Random Forests and Gradient Boosted Trees) remain a default choice for tabular business and manufacturing data.
